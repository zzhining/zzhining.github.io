# 내용은 있는데 슬라이드가 없을 때 — AI 프롬프트 3가지

---

Genspark나 Gamma로 슬라이드를 만들어본 분들은 알 겁니다.
빠르게 초안을 잡을 때는 유용하지만, 정작 내가 가진 자료를 제대로 담기가 어렵습니다.

AI가 내용을 직접 채우는 방식이라, **이미 내용이 있는 경우**에는 구조가 맞지 않는 일이 생깁니다.

이 글에서 소개하는 방식은 반대입니다.
내용은 내가 갖고 있고, 시각화와 디자인만 AI에게 맡깁니다.

---

## 이 방법이 맞는 상황

세 가지 상황에 각각 다른 프롬프트를 씁니다.

**상황 A.** 보고서, 기획서, 분석 문서가 있는데 → 슬라이드 한 장으로 정리해야 할 때  
**상황 B.** 슬라이드는 있는데 → 디자인이 마음에 안 들어서 다시 손봐야 할 때  
**상황 C.** 상품 스펙 문서가 있는데 → 소비자용 상세 페이지로 바꿔야 할 때

반대로, 주제만 있고 내용은 AI가 채워줘도 되는 경우라면 Genspark나 Gamma가 더 빠릅니다.

---

## 처음 쓰는 분을 위한 사용 흐름

복잡하지 않습니다. 네 단계면 됩니다.

**① AI 도구 열기**  
Claude, ChatGPT, Gemini 중 아무거나 괜찮습니다. 이미지 첨부가 필요한 상황 B는 Claude나 ChatGPT를 권장합니다.

**② 아래 프롬프트 복사해서 붙여넣기**  
상황에 맞는 프롬프트를 채팅창에 그대로 붙여넣습니다.

**③ 내 자료 첨부하기**  
상황 A, C는 PDF나 텍스트 문서를 첨부합니다. 상황 B는 슬라이드를 캡처한 이미지를 첨부합니다.

**④ 결과물 받고 대화로 다듬기**  
처음 결과가 완벽하지 않아도 됩니다. 같은 대화창에서 "이 부분 더 강조해줘", "여백 늘려줘" 식으로 이어서 수정하면 됩니다.

출력물은 **React 컴포넌트(.jsx)** 또는 **SVG 파일** 형식으로 받습니다.  
SVG는 PowerPoint에서 바로 열어 편집할 수 있습니다.

---

## 프롬프트 A — 문서를 한 장 슬라이드로

보고서, 기획서, 분석 자료처럼 분량 있는 문서를 한 장짜리 발표 슬라이드로 압축할 때 씁니다.

> **이럴 때 특히 유용합니다:** 임원 보고용 요약 슬라이드가 필요할 때, 또는 데이터가 많아서 어떤 차트로 보여줄지 판단이 서지 않을 때.

```
역할: 당신은 복잡한 정보를 단 한 장의 슬라이드로 압축하는 시각 커뮤니케이션 전문가입니다.

목표: 아래 문서를 읽고, 핵심 메시지가 30초 안에 전달되는 슬라이드 한 장을 제작하세요.

[작업 순서 — 반드시 이 순서대로 진행]

STEP 1. 문서 전체를 읽고, "이 문서가 말하고 싶은 한 가지"를 한 문장으로 정의하세요.
STEP 2. 그 핵심 메시지를 뒷받침하는 수치, 사실, 근거를 최대 5개만 선별하세요.
STEP 3. 선별한 정보를 시각적 계층으로 배치 계획을 세우세요.
         → 제목(핵심 메시지) → 핵심 지표(숫자/차트) → 보조 설명
STEP 4. 각 데이터에 가장 적합한 차트 유형을 선택하고, 선택 이유를 한 줄로 설명하세요.
STEP 5. 위 계획을 바탕으로 슬라이드를 제작하세요.

[제약 조건]
- 슬라이드 1장 / 비율 16:9
- 텍스트 블록 금지 — 모든 설명은 도형, 아이콘, 차트로 표현
- 색상 팔레트: 차콜 (#2B2B2B), 크림 화이트 (#F7F4EF), 코럴 (#E05A3A), 라이트 그레이 (#D4D0C8)
- 폰트: Pretendard (제목 Bold 20pt 이상 / 본문 Regular 13pt 이상)

[금지 사항]
- 원문 문장을 그대로 복사하지 마세요
- 6가지 이상의 색상을 사용하지 마세요
- 중요도가 같아 보이는 요소들을 동일한 크기로 나열하지 마세요

[출력 형식]
① React 컴포넌트 (.jsx) — 브라우저 미리보기용
② SVG 파일 — PowerPoint 편집용

<document>
[문서 내용을 여기에 붙여넣으세요]
</document>
```

## 프롬프트 B — 기존 슬라이드 디자인 수정하기

내용은 확정됐는데 디자인이 마음에 들지 않을 때 씁니다.
기존 슬라이드를 캡처한 이미지를 첨부하고 아래 프롬프트를 사용합니다.

> **이럴 때 특히 유용합니다:** 팀에서 받은 자료를 발표용으로 다듬어야 할 때, 또는 텍스트 위주로만 구성된 슬라이드에 구조와 시각 요소를 입히고 싶을 때.

```
역할: 당신은 기업 발표 자료를 전문으로 하는 비주얼 디렉터입니다.

작업: 첨부한 슬라이드 이미지를 분석하고, 아래 기준에 따라 완전히 재디자인하세요.

[리디자인 전 — 먼저 진단하세요]

아래 세 가지를 짧게 작성하세요:
① 현재 슬라이드에서 가장 눈에 띄는 요소는 무엇인가? 그래야 마땅한가?
② 시선의 흐름이 자연스러운가? 어색한 지점이 있다면 어디인가?
③ 제거해도 메시지 전달에 영향이 없는 요소는 무엇인가?

[리디자인 기준]

① 정보 위계: 제목 > 핵심 메시지 > 보조 정보 순으로 시각적 무게감을 차등 부여
② 여백: 콘텐츠 영역이 전체 슬라이드의 65%를 넘지 않도록 제한
③ 색상: 강조색은 1가지만 사용, 나머지는 중립 계열로 통일
④ 타이포그래피: 폰트 종류 최대 2가지, 크기 단계 최대 3가지

[기술 사양]
- 비율: 16:9
- 폰트: Pretendard
- 색상: 슬라이드 내용의 성격(발표 목적, 대상 청중)을 고려해 색상 조합을 직접 제안하고, 선택 이유를 한 줄로 설명하세요
- 출력 형식: HTML/CSS (브라우저에서 바로 미리볼 수 있도록)

이미지: [슬라이드 캡처 이미지 첨부]
```

## 프롬프트 C — 스펙 문서를 상품 상세 페이지로

상품 기획서나 스펙 문서를 소비자가 이해할 수 있는 온라인 상세 페이지로 바꿀 때 씁니다.
제품 담당자, 소규모 셀러, 스타트업 팀처럼 상세 페이지를 직접 만들어야 하는 상황에 유용합니다.

> **이럴 때 특히 유용합니다:** 스펙은 있는데 소비자 언어로 어떻게 바꿀지 막막할 때, 또는 개발팀이 작성한 기술 문서를 마케팅 페이지로 전환해야 할 때.

```
역할: 당신은 기술 스펙 문서를 읽고, 소비자가 구매 결정을 내리는 데 필요한 정보를 감각적으로 전달하는 상세 페이지 기획자입니다.

작업: 아래 스펙 문서를 바탕으로 온라인 쇼핑몰용 상품 상세 페이지를 제작하세요.

[제작 전 분석 — 반드시 먼저 수행]

① 이 상품의 핵심 구매 이유를 한 문장으로 정의하세요.
② 주요 구매 타겟을 설정하세요. (연령대, 라이프스타일, 어떤 상황에서 구매하는가)
③ 경쟁 상품 대비 가장 차별화되는 스펙이나 특징 한 가지를 선택하세요.

[상세 페이지 구성]

① 히어로 섹션
   - 상품명 + 핵심 가치를 담은 한 줄 카피
   - 대표 이미지 영역 (placeholder 처리)

② 핵심 특장점 3가지
   - 스펙 수치가 아닌 '사용자 혜택' 언어로 변환해서 작성
   - 예시: "방수 등급 IPX7" → "갑작스러운 비에도 걱정 없습니다"

③ 주요 스펙 요약표
   - 구매 결정에 영향을 주는 스펙만 선별해 깔끔한 테이블로 정리
   - 전문 용어는 괄호 안에 짧은 설명 추가

④ 사용 시나리오 2가지
   - 이 상품이 실질적인 가치를 발휘하는 구체적인 일상 장면 묘사

⑤ 구매 전 자주 묻는 질문 3개
   - 스펙 문서 내용을 바탕으로 직접 생성 (배송, 호환성, 사용법 등)

[디자인 사양]
- 레이아웃: 모바일 우선 (최대 너비 480px 기준)
- 색상: 상품 카테고리와 타겟 연령에 어울리는 색상 팔레트를 직접 제안하고, 선택 이유를 설명하세요
- 폰트: Pretendard (제목 Bold / 본문 Regular)
- 출력 형식: HTML/CSS 컴포넌트

[금지 사항]
- 스펙 수치를 설명 없이 그대로 나열하지 마세요
- 모든 특징을 동등한 비중으로 나열하지 마세요 — 중요도에 따라 크기와 위치를 차등 배치하세요

<spec>
[스펙 문서를 여기에 붙여넣으세요]
</spec>
```

## 마무리

세 프롬프트 모두 공통된 원칙으로 설계되어 있습니다.

AI에게 "만들어줘"가 아니라 **"이 순서로 생각하고, 이 기준으로 만들어줘"** 라고 지시하는 방식입니다.
분석 단계를 먼저 거치게 하고, 제약 조건과 금지 사항을 명시하면 결과물의 품질이 눈에 띄게 달라집니다.

처음 결과가 완벽하지 않다면, 프롬프트를 다시 수정하기보다 같은 대화창에서 이어서 지시하는 게 더 빠릅니다.
