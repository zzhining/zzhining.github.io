회사에서 "이 매뉴얼 읽고 정리해줘"라는 업무를 받아본 적 있다면 어떤 일인지 안다. 300페이지짜리 제품 매뉴얼, 200페이지 법령 해설집, 100페이지 계약서. 중요한 내용만 뽑아서 팀에 공유하거나, 신입사원 교육 자료로 만들거나, 자주 묻는 질문 목록으로 정리하는 일이다.

ChatGPT에 PDF를 올리면 요약은 해준다. 하지만 결과를 파일로 저장하려면 복사해야 하고, 여러 PDF를 처리하려면 하나씩 반복해야 하고, 100페이지가 넘으면 "파일이 너무 큽니다"라는 메시지를 마주한다.

**Claude Code는 다르다.** 폴더 안의 PDF 파일들을 읽고, 지정한 형식의 문서를 만들고, 파일로 저장까지 자동으로 처리한다. 이 가이드에서 그 방법을 단계별로 안내한다.

---

## 1. 시작 전 확인 — 내 PDF가 어떤 종류인지 파악한다

모든 PDF가 같은 방식으로 처리되지 않는다. 시작 전에 내 파일이 어느 유형인지 파악해야 한다.

**PDF 유형 판별 방법**

PDF를 열고 텍스트를 마우스로 드래그해서 선택해 본다.

| 결과 | 유형 | 처리 방식 |
|---|---|---|
| 텍스트가 선택된다 | 텍스트 기반 PDF | Claude Code 직접 처리 가능 ✓ |
| 텍스트가 선택되지 않는다 | 스캔(이미지) PDF | OCR 변환 필요 (별도 과정) |
| 파일을 열 때 비밀번호를 요구한다 | 암호화 PDF | 처리 불가. 암호 해제 후 진행 |

**페이지 수 확인**

PDF 뷰어 하단 또는 파일 정보에서 전체 페이지 수를 확인한다.

| 페이지 수 | 처리 방식 |
|---|---|
| 100페이지 이하 | Claude Code 직접 처리 (가장 간단) |
| 100~500페이지 | pdfplumber로 분할 후 처리 |
| 500페이지 이상 | 섹션별로 나눠서 단계적 처리 |

**파일 크기 확인**

파일 탐색기에서 우클릭 → 속성으로 파일 크기를 확인한다. Claude의 시각적 분석 한도는 파일당 100페이지 또는 30MB이며, 두 한도 중 하나라도 초과하면 오류가 발생한다.

## 2. 준비물

- **Claude Code 설치 완료** (1편 기준)
- **Claude Pro 또는 Max 플랜**
- **Python 설치** (100페이지 이하 텍스트 PDF는 불필요. 대용량 파일 처리 시 필요)
- **처리할 PDF 파일**

> 📌 **Python 설치 여부 확인 방법**  
> 터미널(맥) 또는 PowerShell(윈도우)에서 `python --version`을 입력한다.  
> 버전 번호가 나오면 설치된 것이다. `command not found`가 나오면 `https://python.org`에서 설치한다.

## 3. 샘플 파일 준비 — PDF가 없어도 따라할 수 있다

실습용 PDF가 없다면 아래 방법으로 샘플을 만든다.

**방법 1 — 무료 샘플 PDF 다운로드**

구글에서 "product manual PDF sample"을 검색하면 무료 샘플 문서를 찾을 수 있다. 또는 공공데이터포털(`data.go.kr`)에서 공개된 PDF 보고서를 내려받아도 된다.

**방법 2 — 워드 파일을 PDF로 변환**

기존에 갖고 있는 `.docx` 파일을 Word에서 열고 **파일 → 다른 이름으로 저장 → PDF**로 저장하면 실습용 PDF가 된다.

파일을 `pdf_work`라는 폴더에 저장해 두고 실습을 시작한다.

## 4. 실습 1 — 100페이지 이하 PDF 직접 처리

가장 간단한 방법이다. 별도 라이브러리 설치 없이 바로 처리할 수 있다.

**Step 1. 폴더로 이동 후 Claude Code 실행**

```bash
# 윈도우
cd "C:\Users\홍길동\Documents\pdf_work"

# 맥
cd /Users/honggildong/Documents/pdf_work

claude
```

**Step 2. 지시 입력 — 시나리오: 제품 매뉴얼 → FAQ + 교육 자료 동시 생성**

```
manual.pdf 파일을 읽어줘.
이 파일을 바탕으로 두 가지 문서를 만들어줘.

첫 번째: faq.md
- 파일 내용을 바탕으로 실무에서 자주 묻는 질문 20개와 답변을 만들어줘.
- 질문은 실제 사용자가 검색할 것 같은 자연스러운 표현으로 작성해줘.
- 각 답변은 3줄 이내로 간결하게 정리해줘.

두 번째: onboarding.md
- 신입사원이 처음 이 제품을 배울 때 알아야 할 핵심 내용만 추려줘.
- 전체 5개 챕터로 구성하고, 각 챕터는 제목 + 핵심 설명 3줄 + 주의사항 1개로 구성해줘.
- 전문 용어는 쉬운 말로 풀어서 설명해줘.

두 파일 모두 한국어로 작성해줘.
```

**Step 3. 결과 확인**

작업 완료 후 `pdf_work` 폴더에 `faq.md`와 `onboarding.md` 두 파일이 생성된다.

## 5. 실습 2 — 100페이지 이상 PDF 처리

100페이지를 초과하는 PDF는 Claude Code가 직접 읽으면 오류가 발생한다. `pdfplumber` 라이브러리를 사용해서 분할 처리하면 된다. Claude Code가 라이브러리 설치와 처리를 모두 자동으로 진행한다.

**프롬프트**

```
large_report.pdf 파일을 처리해야 하는데 100페이지가 넘어.
pdfplumber를 사용해서 50페이지씩 나눠서 읽고
전체 내용을 요약한 executive_summary.md 파일을 만들어줘.

요약 문서 구성:
1. 전체 개요 (3줄)
2. 주요 섹션별 핵심 내용 (각 섹션 5줄 이내)
3. 수치 데이터 및 통계 표 (문서에 등장하는 주요 수치만 추출)
4. 결론 및 시사점 (5줄)

한국어로 작성하고 executive_summary.md로 저장해줘.
```

Claude Code가 pdfplumber를 설치하지 않았다면 먼저 설치를 제안한다. "설치해줘"라고 답하면 자동으로 진행된다.

```
pdfplumber가 설치되지 않았습니다. 지금 설치할까요?
> 응, 설치해줘
```

설치 후 분할 처리가 자동으로 시작된다.

## 6. 실습 3 — 폴더 안의 여러 PDF 일괄 처리

계약서가 10개, 보고서가 20개처럼 여러 PDF를 한꺼번에 처리해야 할 때 사용한다.

**시나리오: 계약서 폴더에서 핵심 조항 추출**

```
contracts 폴더 안의 모든 PDF 파일을 읽어줘.
각 계약서에서 다음 항목을 추출해줘.

1. 계약 당사자 (갑/을)
2. 계약 기간 (시작일 ~ 종료일)
3. 계약 금액 또는 단가
4. 자동 갱신 조항 여부
5. 특이 사항 또는 주요 조건

모든 계약서의 정보를 하나의 표로 정리해서
contract_summary.md로 저장해줘.
처리하지 못한 파일이 있으면 파일 이름과 이유를 summary 하단에 따로 기록해줘.
```

## 7. 실전 프롬프트 모음 — 직군별

**HR 담당 — 취업 규칙 핵심 정리**

```
company_rules.pdf를 읽고
신입사원이 반드시 알아야 할 규정 20가지를 추출해줘.
주제별(근무 시간, 휴가, 복리후생, 징계 등)로 분류하고
각 항목을 1~2줄로 간결하게 정리해줘.
hr_checklist.md로 저장해줘.
```

**법무·컴플라이언스 — 계약서 위험 조항 탐지**

```
contract.pdf를 읽고
다음 항목이 포함돼 있는지 검토해줘.

1. 일방적 계약 해지 조항
2. 손해배상 한도 초과 조항
3. 지식재산권 귀속 조항
4. 경쟁 금지 조항
5. 자동 갱신 조항

각 항목이 있으면 해당 조항 위치(페이지, 조 항목)와 원문 요약을 표시해줘.
위험도를 높음/중간/낮음으로 표시해줘.
결과를 contract_review.md로 저장해줘.
```

**강사·교육 담당 — 강의 교재 퀴즈 생성**

```
lecture_material.pdf를 읽고
객관식 10문항, 단답형 5문항, 서술형 2문항으로 구성된
평가지를 만들어줘.

각 문항에 정답과 해설을 포함해줘.
난이도를 기초/중급/심화로 구분해서 표시해줘.
quiz.md와 quiz_answer.md 두 파일로 나눠서 저장해줘.
(quiz.md에는 정답 없이, quiz_answer.md에는 정답 포함)
```

**마케터 — 백서(White Paper) 핵심 인사이트 추출**

```
whitepaper.pdf를 읽고
다음 세 가지 파일을 만들어줘.

1. sns_post.md: 소셜미디어 공유용 요약 3개
   (각 200자 이내, 핵심 통계 수치 포함)

2. blog_outline.md: 이 백서를 기반으로 한 블로그 포스트 개요
   (제목, 소제목 5개, 각 소제목별 3줄 요약)

3. key_stats.md: 백서에 등장하는 모든 통계와 수치를 표로 정리
   (수치, 출처, 페이지 번호 포함)
```

**연구자·컨설턴트 — 여러 보고서 비교 분석**

```
reports 폴더 안의 PDF 파일들을 읽고
각 보고서의 핵심 주장, 방법론, 결론을 추출해줘.
보고서들 사이의 공통점과 차이점을 비교 분석해줘.
comparative_analysis.md로 저장해줘.
```

## 8. 스캔 PDF 처리 — 별도 과정이 필요하다

텍스트 선택이 안 되는 스캔 이미지 PDF는 Claude Code가 직접 읽지 못한다. OCR(광학 문자 인식) 변환이 먼저 필요하다.

**무료 OCR 변환 방법**

방법 1 — Adobe Acrobat 무료 버전  
Adobe Acrobat Reader DC에서 스캔 PDF를 열고 **도구 → 텍스트 인식**을 클릭한다. 변환된 파일을 저장 후 Claude Code로 처리한다.

방법 2 — 구글 드라이브  
스캔 PDF를 구글 드라이브에 업로드한다. 파일을 우클릭하고 **연결 앱 → Google Docs**를 선택하면 OCR이 자동으로 실행되고 텍스트가 추출된다. 추출된 텍스트를 `.txt` 파일로 저장한 뒤 Claude Code로 처리한다.

방법 3 — Claude Code에서 직접 OCR 요청

```
scanned_document.pdf 파일이 스캔 이미지 PDF야.
pytesseract를 사용해서 OCR을 실행하고
텍스트를 추출한 뒤 scanned_text.txt로 저장해줘.
그 다음 추출된 텍스트를 읽고 주요 내용을 요약해줘.
```

> ⚠️ **OCR 정확도 주의**  
> 스캔 품질이 낮거나 손글씨가 포함된 문서는 OCR 정확도가 크게 떨어진다. 결과물을 반드시 원본과 대조해서 오류 여부를 확인한다.

## 9. 자주 하는 실수와 해결법

**"PDF too large to process" 오류**

100페이지 초과 또는 30MB 초과 파일이다. 실습 2의 pdfplumber 분할 처리 프롬프트를 사용한다.

**일부 페이지 내용이 누락된 것 같을 때**

컨텍스트 창이 초과됐거나 복잡한 표, 그래프 영역을 건너뛴 경우다. 프롬프트에 처리할 범위를 명시한다.

```
report.pdf의 10~50페이지만 읽고 요약해줘.
```

**표와 수치가 뒤섞여 나올 때**

표 구조가 복잡한 PDF에서 자주 발생한다. 프롬프트를 수정해서 표만 따로 처리하도록 지시한다.

```
report.pdf에서 표(table)만 찾아서 추출해줘.
각 표를 번호 순서대로 정리하고 표 제목과 출처 페이지를 함께 표시해줘.
tables.md로 저장해줘.
```

**암호화된 PDF**

Claude Code로 처리 불가능하다. PDF 발행 기관에 암호 해제 버전을 요청하거나, 권한 범위 내에서 복사 가능한 버전을 별도로 확보한 뒤 처리한다.

**이전 작업 이어서 하기**

```bash
claude --resume
```

이전 세션에서 처리한 파일 정보가 남아 있어서 같은 설명을 반복하지 않아도 된다.

## 10. ChatGPT와 무엇이 다른가

| 상황 | ChatGPT | Claude Code |
|---|---|---|
| PDF 처리 방식 | 1개씩 업로드 | 폴더 경로 지정으로 일괄 처리 |
| 결과물 저장 | 직접 복사 필요 | 지정 파일명으로 자동 저장 |
| 여러 산출물 동시 생성 | 한 번에 하나 | FAQ + 교육자료 동시 생성 가능 |
| 100페이지 이상 처리 | 불가 | pdfplumber 분할 처리로 가능 |
| 여러 PDF 비교 분석 | 파일마다 개별 작업 | 폴더 전체를 한 번에 비교 |

---

다섯 편에 걸친 시리즈를 마치며 공통 패턴이 하나 있다. **"한 번에 하나씩 처리하던 일을 묶어서 위임하는 것."** 파일, 엑셀, 보고서, 리서치, PDF. 모두 같은 원리다. 방법을 익히면 다음 업무에 응용하는 것은 어렵지 않다.
