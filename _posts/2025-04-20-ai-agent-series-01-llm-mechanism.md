AI 도구를 쓰다 보면 같은 질문을 해도 어떤 날은 답이 좋고, 어떤 날은 엉뚱하다.
프롬프트를 조금 바꿨을 뿐인데 결과가 완전히 달라지기도 한다. 
AI 교육 현장에서 강의를 진행하다 보면, 수강생들이 가장 많이 묻는 것이 바로 이것이다.

> "ChatGPT가 왜 이런 답을 했을까요?"

이 질문에 제대로 답하려면 AI 도구의 사용법이 아니라, 내부에서 무슨 일이 벌어지는지를 먼저 알아야 한다. 
이 시리즈는 AI Agent를 설계하는 사고법을 다룬다. 
Dify, n8n, LangChain 같은 도구는 그 흐름을 눈으로 확인하는 수단으로만 활용한다. 
1편에서는 모든 AI 도구의 기반이 되는 LLM(Large Language Model)이 어떻게 작동하는지를 정리한다.

---

## 1. LLM은 "다음 단어를 예측하는 기계"이다

LLM의 본질은 단순하다. 주어진 텍스트 다음에 올 가능성이 가장 높은 단어를 계속 이어붙이는 것이다. 

"서울의 봄은 ___"라는 입력이 들어오면, AI는 내부적으로 수많은 단어 후보에 확률을 부여한다.

![확률 분포 예시](/assets/image/ai-agent-01/prob-distribution.png)

이 확률 계산에 쓰이는 수식이 Softmax다. 수학적으로 깊게 들어갈 필요는 없다. 
중요한 것은 **AI가 정답을 아는 것이 아니라 확률적으로 그럴듯한 것을 고르는 것**이라는 사실이다. 
이것이 AI가 틀린 말을 자신 있게 하는 이유다.

---

## 2. 텍스트는 어떻게 AI에게 전달되는가: 토큰화

AI는 문장을 있는 그대로 읽지 않는다. 텍스트를 "토큰"이라는 최소 단위로 쪼갠 뒤, 각각을 숫자 ID로 변환해서 처리한다.

```
입력: "서울의 봄"
토큰: ["서울", "의", " 봄"]
ID:   [3421, 210, 8942]
```

한국어는 영어보다 토큰 수가 많이 나온다. 
같은 의미를 표현해도 한국어로 쓰면 토큰이 더 소모되고, 그만큼 비용도 올라간다. 
실무에서 프롬프트 길이를 관리해야 하는 이유가 여기 있다.

또 하나 알아둘 것이 있다. 모델마다 토큰화 방식이 다르다. GPT-4와 Claude, Llama는 서로 다른 사전(Vocabulary)을 사용한다. 
같은 텍스트라도 모델에 따라 토큰 수가 달라진다.

---

## 3. LLM은 어떻게 학습하는가: 두 단계

<!-- [이미지: 사전학습 → 파인튜닝 2단계 흐름도. 왼쪽: 인터넷 텍스트 → Base Model, 오른쪽: 지시 데이터 → Instruct Model] -->
![사전학습-파인튜닝 2단계](/assets/image/ai-agent-01/pretrain-finetune.png)

LLM의 학습은 크게 두 단계로 나뉜다.

### 1단계: 사전학습(Pre-training)

인터넷, 책, 뉴스 등 방대한 텍스트를 읽으며 다음 토큰 예측을 반복한다. 
이 단계의 결과물이 Base Model이다. Base Model은 텍스트를 자연스럽게 이어 쓰는 능력은 뛰어나지만, 질문에 답하는 능력은 부족하다.

### 2단계: 파인튜닝(Fine-tuning)

"지시어 + 입력 + 응답" 형태의 정제된 데이터로 추가 학습한다. 
여기에 인간 피드백 기반 강화학습(RLHF)을 더하면, 우리가 실제로 사용하는 Instruct Model이 완성된다.

Base Model과 Instruct Model의 차이를 직접 비교하면 이렇다.

| 질문 | Base Model | Instruct Model |
|---|---|---|
| "서울의 명소 3곳은?" | "서울의 명소 3곳은? 1. 경복궁 2. 남산..." (질문을 그대로 이어 씀) | "서울의 대표 명소는 경복궁, N서울타워, 북촌 한옥마을입니다." |
| "이메일 요약해줘" | 본문을 그대로 이어 붙임 | "핵심은 프로젝트 일정 변경과 회의 요청입니다." |

우리가 쓰는 ChatGPT, Claude, Gemini는 모두 Instruct Model이다. 
"질문에 답하는 AI"가 당연하게 느껴지지만, 그 뒤에는 방대한 파인튜닝 작업이 있다.

---

## 4. Closed-source vs Open-weight: 어떤 모델을 쓸 것인가

현재 LLM 시장은 크게 두 진영으로 나뉜다.

**Closed-source (상용 모델)**
- GPT-4o, Claude, Gemini
- API 키 하나로 즉시 사용 가능
- 데이터가 외부 서버로 전송됨
- 사용량 기반 과금

**Open-weight (오픈 모델)**
- Meta Llama, Qwen, Mistral
- 서버에 직접 설치해서 운영
- 데이터가 외부로 나가지 않음
- 서버 비용은 발생하지만 API 비용은 없음

기업 교육 현장에서 많이 받는 질문 중 하나가 "어떤 모델을 써야 하나요?"이다. 
정답은 없다. 
당연히 예상했겠지만 민감한 사내 데이터를 다루는 금융·공공기관이라면 오픈 모델 자체 호스팅이 맞고, 
빠르게 프로토타입을 만들어야 한다면 Closed-source가 맞다. 
용도와 보안 요건에 따라 선택한다.

덧, 보안을 겁내다가 시작조차 못하면 엄청나게 뒤쳐지게 된다.
당신이 다루는 정보가 정말로 보안이 중요한 자료인가? 잘 생각해봐라.

## 5. 프롬프트가 중요한 진짜 이유

LLM의 작동 원리를 이해하면, 프롬프트가 왜 중요한지가 자연스럽게 보인다. 
AI는 입력된 텍스트를 기반으로 확률을 계산한다. 즉, **입력의 맥락이 달라지면 확률 분포 자체가 달라진다.**


<!-- [이미지: 동일 질문에 프롬프트 추가 전/후 출력 비교. 왼쪽: "요약해줘" → 짧고 불완전한 답변, 오른쪽: Role+Task+Format 지정 → 구조화된 답변] -->
![프롬프트 전후 비교](/assets/image/ai-agent-01/prompt-comparison.png)
구글이 제시한 프롬프트 설계 5대 원칙은 이 원리 위에 세워진 것이다.

1. **Role**: 누구의 관점에서 답할 것인가
2. **Task**: 무엇을 수행할 것인가
3. **Context**: 어떤 배경과 제약이 있는가
4. **Few-shot**: 원하는 답의 패턴을 예시로 제시
5. **Format**: 어떤 형태로 출력할 것인가

이 다섯 가지는 다음 편에서 실무 프롬프트 템플릿과 함께 상세히 다룬다.

---

## 6. 정리

지금까지 이야기한 내용을 정리하면 다음과 같다.
LLM은 "다음에 올 확률이 가장 높은 토큰을 이어붙이는 시스템"이다. 
정답을 아는 것이 아니다. 그래서 같은 질문을 해도 매번 답이 다를 수 있고, 틀린 내용을 자신 있게 말하기도 한다.

이 특성을 이해하면 AI를 쓰는 방식이 달라진다. 
"AI가 알아서 잘 해주겠지"가 아니라, "내가 어떤 맥락을 제공하느냐에 따라 결과가 달라진다"는 관점으로 전환된다. 
그것이 프롬프트 설계의 시작이고, AI Agent 설계의 출발점이다.
