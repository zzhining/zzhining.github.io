"프롬프트를 잘 써야 한다"는 말은 많이 들었다. 그런데 정작 "어떻게"가 빠진 경우가 대부분이다. 기업 교육 현장에서 18년차 실무자로 강의를 진행하다 보면, 수강생들이 가장 아쉬워하는 지점이 바로 여기다.

> "열심히 썼는데 왜 원하는 답이 안 나오죠?"

1. 1편에서 다뤘듯이 LLM은 입력된 맥락을 바탕으로 확률을 계산한다. 맥락이 빈약하면 AI는 가장 일반적인 답을 내놓는다. 즉, 프롬프트는 "AI에게 부탁하는 말"이 아니라 **"AI가 올바른 확률 분포를 계산하도록 맥락을 설계하는 작업"**이다. 2편에서는 구글이 제시한 프롬프트 설계 5원칙을 기업 실무에 바로 적용할 수 있는 형태로 정리한다.

---

## 1. 왜 구글의 5원칙인가

2. 프롬프트 작성법을 다루는 콘텐츠는 많다. 그 중 구글의 5원칙을 기준으로 삼은 이유는 하나다. AI 모델을 가장 많이 만들고, 가장 많이 써본 조직이 정리한 원칙이기 때문이다. 특정 도구나 모델에 종속되지 않고, GPT든 Claude든 Gemini든 동일하게 적용된다.

3. 5원칙은 다음과 같다.

| 원칙 | 핵심 질문 | 한 줄 설명 |
|---|---|---|
| Role | 누구로서 답할 것인가 | AI에게 정체성을 부여 |
| Task | 무엇을 할 것인가 | 동사 중심으로 행동을 명시 |
| Context | 어떤 상황인가 | 배경, 제약, 대상 정보 제공 |
| Few-shot | 어떤 형태의 답을 원하는가 | 입력-출력 예시를 제시 |
| Format | 어떻게 출력할 것인가 | 구조, 길이, 형식을 지정 |

---

## 2. 원칙 1: Role (역할 정의)

4. AI에게 역할을 주면 답변의 관점과 어휘가 달라진다. 역할 없이 질문하면 AI는 가장 일반적인 관점에서 답한다. 역할을 부여하면 특정 전문가의 관점으로 좁혀진다.

<!-- [이미지: 역할 없는 프롬프트 vs 역할 있는 프롬프트 출력 비교. 왼쪽: "마케팅 전략 알려줘" → 교과서적 답변, 오른쪽: "너는 B2B SaaS 마케팅 10년 경력자야. 마케팅 전략 알려줘" → 구체적 실무 답변] -->

**작성 예시**
```
당신은 노련한 비즈니스 커뮤니케이션 전문가입니다.
당신은 데이터 분석 10년 경력의 시니어 컨설턴트입니다.
당신은 초등학생에게 과학을 가르치는 선생님입니다.
```

5. 주의할 점이 있다. 역할은 구체적일수록 좋다. "전문가"보다 "B2B 영업 10년 경력의 전문가"가 낫다. 역할이 모호하면 AI가 역할을 스스로 해석하고, 그 해석이 내가 원하는 것과 다를 수 있다.

---

## 3. 원칙 2: Task (작업 정의)

6. Task는 동사로 시작해야 한다. "~에 대해 이야기해줘"가 아니라 "~을 분석하고 3가지로 요약해줘"처럼 행동을 명시한다.

**모호한 Task vs 명확한 Task**

```
[모호] 이 이메일에 대해 이야기해줘.
[명확] 이 이메일을 읽고, 핵심 요청사항을 2줄로 요약하고,
       답장 초안을 정중한 톤으로 작성해줘.
```

7. Task가 여러 개라면 번호를 매겨서 순서대로 나열한다. AI는 순서를 따른다. 순서가 없으면 중요한 것을 빠뜨리거나 순서가 뒤바뀐 결과가 나온다.

---

## 4. 원칙 3: Context (맥락 제공)

8. Context는 프롬프트 5원칙 중 실무에서 가장 많이 생략되는 부분이다. 그리고 가장 큰 차이를 만드는 부분이기도 하다. AI는 내가 처한 상황을 모른다. 내가 알려줘야 한다.

Context에 넣어야 할 정보는 세 가지다.

- **대상**: 결과물을 누가 읽는가 (예: 비개발자 임원진, 신입사원, 외부 고객)
- **제약**: 분량, 사용 불가 표현, 참고하지 말아야 할 내용
- **배경**: AI가 모를 수 있는 내부 상황, 이전 맥락

**예시**
```
대상: 임원진 (비개발자)
제약: 기술 용어 사용 금지, 3분 이내에 읽을 수 있는 분량
배경: 이번 분기 AI 도입 TF의 중간 보고용 문서
```

---

## 5. 원칙 4: Few-shot (예시 제시)

9. Few-shot은 원하는 답변의 패턴을 "입력 → 출력" 쌍으로 보여주는 것이다. 말로 설명하는 것보다 예시 하나가 훨씬 강력하다.

<!-- [이미지: Few-shot 프롬프트 구조 다이어그램. "예시 1: 입력 → 출력, 예시 2: 입력 → 출력, 실제 질문: 입력 → ?" 형태의 흐름] -->

**예시**
```
아래 형식으로 회의록 한 줄 요약을 작성해줘.

예시 1)
입력: "예산 증액 논의, 담당자 미정, 다음 주 재논의 예정"
출력: "[미결] 예산 증액 건 - 담당자 지정 후 차주 재논의"

예시 2)
입력: "신규 온보딩 프로세스 확정, 인사팀 담당, 5월 적용"
출력: "[완료] 온보딩 프로세스 확정 - 인사팀 주관, 5월 시행"

입력: "마케팅 캠페인 방향성 논의, 결론 없이 종료"
출력:
```

10. Few-shot은 특히 출력 형식이 고정되어야 하는 반복 업무에 효과적이다. 보고서 포맷, 이메일 양식, 데이터 정리 규칙 등에 적용하면 일관된 결과를 얻는다.

---

## 6. 원칙 5: Format (출력 형식)

11. Format은 결과물의 구조와 길이를 지정하는 것이다. 지정하지 않으면 AI는 스스로 판단해서 출력한다. 그 판단이 내가 원하는 것과 다를 수 있다.

**자주 쓰는 Format 지정 방식**

```
- 마크다운 표 형태로 출력할 것
- 3개의 bullet point로 요약할 것
- 500자 이내로 작성할 것
- JSON 형식으로 출력할 것 {"key": "value"}
- 제목, 본문, 결론 구조로 작성할 것
```

12. Format은 다음 편에서 다룰 워크플로우 설계와 직결된다. 워크플로우에서 한 노드의 출력이 다음 노드의 입력으로 들어갈 때, Format이 명확하지 않으면 다음 단계에서 파싱이 실패한다. JSON 형식 지정이 특히 중요한 이유다.

## 7. 5원칙을 조합한 실무 템플릿

13. 5원칙을 모두 조합하면 이런 구조가 된다.

<!-- [이미지: 5원칙 조합 프롬프트 구조 다이어그램. Role → Context → Task → Few-shot → Format 순서로 블록이 쌓이는 형태] -->

**템플릿 1: 비즈니스 이메일 교정**
```
# Role
당신은 격식 있는 문체를 구사하는 비즈니스 커뮤니케이션 전문가입니다.

# Context
- 수신인: {{recipient}} (예: 외부 거래처 담당자)
- 원하는 톤: {{tone}} (예: 전문적이고 정중한)

# Task
제공된 이메일 초안을 아래 기준에 따라 재작성하세요.
1. 문법 및 맞춤법 교정
2. 상황에 맞는 인사말과 맺음말 추가
3. 지정된 톤에 맞게 어휘 조정
4. 핵심 메시지는 변경하지 말 것

# Input
이메일 초안: {{email_draft}}

# Format
---
[교정된 이메일]
(최종 내용 작성)
---
[수정 포인트]
- 개선 사항 2~3개를 bullet로 설명
```

**템플릿 2: 문서 기반 질의응답 (RAG용)**
```
# Role
당신은 제공된 문서를 바탕으로 질문에 답하는 전문 컨설턴트입니다.

# Instructions
- 반드시 아래 [Context] 내의 정보만 사용할 것
- Context에서 답을 찾을 수 없다면 "제공된 문서에서 관련 정보를 찾을 수 없습니다"라고 답할 것
- 답변 뒤에 출처 문서 번호를 명시할 것 (예: [문서 1])

# Context
{retrieved_chunks}

# Question
{user_query}
```

**템플릿 3: 데이터 분석 리포트**
```
# Role
당신은 데이터 분석 전문가이자 비즈니스 전략 컨설턴트입니다.

# Task
제공된 데이터를 분석하고 아래 구조로 리포트를 작성하세요.

# Format
## Executive Summary
전체 분석의 핵심을 3문장 이내로 요약

## Key Insights
- [지표 A]: 현황 및 특징
- [지표 B]: 전기 대비 변동 및 원인

## 강점 / 약점
- 강점: 잘 되고 있는 점
- 약점: 개선이 필요한 점

## Action Plan
- 단기 실행 과제
- 장기 전략적 조언
```

## 8. 정리: 프롬프트는 설계다

14. 좋은 프롬프트는 AI를 설득하는 것이 아니다. AI가 올바른 방향으로 확률을 계산하도록 **맥락을 구조화하는 것**이다. Role로 관점을 잡고, Task로 행동을 지정하고, Context로 상황을 전달하고, Few-shot으로 패턴을 보여주고, Format으로 출력을 통제한다.

15. 이 다섯 가지가 갖춰진 프롬프트는 반복 사용이 가능한 템플릿이 된다. 그리고 템플릿이 되면, 다음 편에서 다룰 워크플로우의 핵심 구성 요소가 된다. 사람이 매번 입력하는 것이 아니라, 시스템이 자동으로 채워 넣는 구조로 발전한다.
