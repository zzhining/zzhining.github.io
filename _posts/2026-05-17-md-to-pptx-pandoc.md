Claude나 Gemini에게 "이 내용으로 PPT 만들어줘"라고 요청하면 꽤 그럴듯한 슬라이드가 나온다. 처음 한두 번은 신기하다. 그런데 실무에서 계속 쓰다 보면 이런 상황을 마주하게 된다.

"레이아웃이 마음에 안 드는데, 수정 요청을 몇 번 하다 보니 토큰이 다 떨어졌다."

PPTX 파일을 AI가 직접 생성하고 수정하는 방식은 토큰 소모가 크다. 파일을 통째로 읽고 다시 쓰는 작업을 반복하기 때문이다. 수정이 잦은 실무 보고서일수록 이 방식의 한계가 빠르게 드러난다.

디자인이 중요하지 않은 보고서라면 접근 방식을 바꾸는 게 낫다. **내용 구성과 변환을 분리**하는 것이다.

1. AI와 함께 내용을 Markdown 파일로 작성한다
2. 로컬에 설치한 Pandoc으로 PPTX로 변환한다

Markdown은 텍스트 파일이라 토큰 소모가 적고, 수정이 자유롭다. 변환은 명령어 한 줄로 끝난다.

---

## 1. Pandoc이란 무엇인가

Pandoc은 문서 형식을 변환하는 오픈소스 도구다. Markdown, HTML, Word, PDF, PPTX, Beamer 등 수십 가지 형식 간 변환을 지원한다. 설치하면 터미널에서 명령어 한 줄로 파일을 변환할 수 있다.

공식 사이트: [pandoc.org](https://pandoc.org)

---

## 2. Pandoc 설치

**Windows**

명령 프롬프트나 PowerShell을 열고 아래 명령어를 실행한다.

```
winget install pandoc
```

winget이 없다면 [pandoc.org/installing.html](https://pandoc.org/installing.html)에서 설치 파일을 직접 내려받는다.

**macOS**

Homebrew가 설치되어 있다면:

```
brew install pandoc
```

**설치 확인**

터미널에서 버전을 확인한다.

```
pandoc --version
```

버전 정보가 출력되면 설치가 완료된 것이다.

## 3. Markdown 파일 작성 규칙

Pandoc이 슬라이드를 만드는 방식은 단순하다. **헤딩 레벨(`#`의 개수)에 따라 페이지가 나뉜다.**

| 마크다운 | 슬라이드에서의 역할 |
|---|---|
| `#` (H1) | 섹션 구분 슬라이드 (표지처럼 사용) |
| `##` (H2) | 새로운 슬라이드 시작 |
| `###` (H3) | 슬라이드 내 소제목 |
| `---` | 강제 슬라이드 전환 |

아래 구조를 기준으로 Markdown 파일을 작성하면 된다.

```markdown
---
title: 보고서 제목
author: 작성자 이름
date: 2026-05-17
---

# 섹션 이름

## 슬라이드 제목

- 핵심 내용 1
- 핵심 내용 2
- 핵심 내용 3

## 다음 슬라이드 제목

본문 텍스트나 표, 목록을 넣는다.

| 항목 | 내용 |
|---|---|
| A | 설명 |
| B | 설명 |

# 다음 섹션

## 결론

- 요약 1
- 요약 2
```

**작성 시 주의사항:**
- 한 슬라이드에 내용을 너무 많이 넣으면 PPTX에서 텍스트가 넘친다. `##` 하나당 불릿 포인트 4~6개 이내를 권장한다.
- 이미지는 `![설명](파일경로.png)` 형식으로 넣을 수 있다.
- 표는 Markdown 표 문법 그대로 슬라이드에 반영된다.

## 4. PPTX로 변환하는 명령어

Markdown 파일이 준비되었다면 터미널에서 아래 명령어를 실행한다.

```
pandoc 파일명.md -o 결과물.pptx
```

예시:

```
pandoc report.md -o report.pptx
```

명령어를 실행한 폴더에 `report.pptx` 파일이 생성된다.

**슬라이드 레벨을 명시적으로 지정하고 싶다면:**

```
pandoc report.md --slide-level=2 -o report.pptx
```

`--slide-level=2`는 H2(`##`)를 슬라이드 구분 기준으로 삼겠다는 뜻이다. 생략해도 기본값이 H2이지만, 명시하면 의도가 명확해진다.

---

## 5. 디자인 템플릿 적용하기

Pandoc 기본 변환은 디자인이 단순하다. 회사 템플릿이나 미리 꾸며둔 PPTX를 기준 형식으로 지정하면 해당 테마를 그대로 가져온다.

```
pandoc report.md --reference-doc=template.pptx -o report.pptx
```

`template.pptx`는 레이아웃과 색상, 폰트가 설정된 기준 파일이다. Pandoc은 이 파일의 디자인 설정을 유지하면서 내용만 채워 넣는다.

템플릿 파일을 한 번 만들어두면 매번 같은 디자인으로 변환된다.

## 6. AI와 함께 쓰는 실전 흐름

아래 순서로 작업하면 토큰 낭비 없이 보고서를 완성할 수 있다.

**1단계: AI에게 Markdown 초안 요청**

```
아래 주제로 발표용 보고서 Markdown 파일을 작성해줘.
## 가 새 슬라이드를 의미하고, # 은 섹션 구분이야.
슬라이드당 불릿 포인트는 5개 이내로 유지해줘.

주제: [보고서 주제 입력]
```

**2단계: 텍스트 편집기에서 내용 수정**

AI가 생성한 Markdown을 VSCode나 메모장에서 자유롭게 수정한다. 텍스트 파일이므로 수정에 토큰이 소모되지 않는다.

**3단계: Pandoc으로 변환**

```
pandoc report.md --slide-level=2 -o report.pptx
```

**4단계: 필요하면 PowerPoint에서 최종 조정**

변환된 PPTX를 열어 디자인 요소만 추가로 조정한다.

---

## 7. 이 방식이 맞는 상황과 맞지 않는 상황

**맞는 상황**
- 내용 전달이 주목적인 내부 보고서
- 반복적으로 수정이 일어나는 작업물
- 동일한 형식의 보고서를 여러 번 만들어야 할 때

**맞지 않는 상황**
- 비주얼이 중요한 외부 발표 자료
- 이미지, 차트, 인포그래픽이 핵심인 슬라이드
- 디자이너와 협업하는 공식 보고서

---

Pandoc은 설치 후 명령어 하나로 변환이 끝나는 도구다. 처음 한 번만 설치해두면 이후로는 Markdown 파일만 관리하면 된다. AI로 초안을 잡고, 텍스트로 다듬고, Pandoc으로 변환하는 흐름이 자리 잡히면 PPT 작업에서 토큰을 소모할 이유가 없어진다.
