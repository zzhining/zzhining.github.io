AI에게 보고서를 맡기는 방식은 크게 두 가지로 나뉜다.

하나는 "이 내용으로 PPT 만들어줘"라고 하는 것이다. AI가 처음부터 끝까지 만들어준다. 빠르고 편하다. 그런데 결과물이 마음에 들지 않을 때 수정을 요청하기 시작하면 금방 한계에 부딪힌다. 파일을 통째로 읽고 다시 쓰는 과정에서 토큰이 빠르게 소모되고, 어느 순간 "더 이상 작업을 이어갈 수 없습니다"라는 메시지를 보게 된다.

다른 하나는 AI에게 **SVG 파일을 만들게 하고**, 그 파일을 내가 직접 편집하는 방식이다. 구조는 복잡해 보이지만, 실제로 써보면 통제권이 훨씬 명확해진다.

---

## 1. AI에게 문서 전체를 맡기는 방식의 현실

AI가 PPT나 보고서를 A to Z로 만들어주는 방식의 장점은 분명하다.

**장점**
- 초안을 빠르게 볼 수 있다
- 특별한 도구 없이 바로 결과물이 나온다
- 반복적인 레이아웃 작업을 건너뛸 수 있다

**단점**
- AI가 선택한 디자인 결정을 바꾸기 어렵다
- 수정 요청이 반복될수록 토큰 소모가 급격히 늘어난다
- 회사 브랜드 가이드라인이나 특정 레이아웃 요구사항을 정확히 반영하기 어렵다
- PPTX로 직접 출력하는 경우, AI가 파일 내부 구조 전체를 조작하므로 예측하기 어려운 오류가 생길 수 있다

요약하면, AI가 만들어준 결과물을 **그대로 쓸 때**는 빠르다. 하지만 내가 원하는 모양으로 **다듬으려는 순간**부터 비효율이 시작된다.

## 2. SVG를 중간 단계로 쓰는 방식

SVG(Scalable Vector Graphics)는 텍스트로 작성된 벡터 이미지 파일이다. XML 기반이라 텍스트 편집기에서 열면 코드가 보이고, Inkscape나 Adobe Illustrator 같은 벡터 편집 도구에서 요소별로 수정할 수 있다. 완성된 SVG는 PowerPoint에 그림으로 삽입하거나, 그대로 발표 자료로 사용할 수 있다.

이 방식의 핵심은 **역할 분리**다.

- AI: 데이터 분석 + 시각화 구조 설계 + 초기 디자인
- 나: 색상 조정, 텍스트 수정, 레이아웃 미세 조정

AI가 한 번 SVG를 만들어주면, 이후 수정은 로컬에서 내가 직접 한다. 토큰을 더 쓸 필요가 없다.

**장점**
- 수정이 자유롭다. AI를 다시 호출하지 않아도 된다
- 벡터 형식이라 크기를 늘려도 깨지지 않는다
- PowerPoint, Figma, Canva 등 다양한 도구에 붙여쓸 수 있다
- 한 번 만든 SVG를 템플릿처럼 재사용할 수 있다
- AI와의 대화에서 토큰을 초안 생성에만 집중할 수 있다

**단점**
- SVG 편집 도구(Inkscape 등)에 익숙하지 않으면 수정이 어렵다
- AI가 생성한 SVG 코드는 복잡한 경우가 많아, 코드 직접 수정은 진입장벽이 있다
- 폰트가 로컬에 설치되어 있지 않으면 텍스트가 다르게 렌더링될 수 있다
- 동적 차트(클릭 인터랙션 등)는 SVG로 구현하기 어렵다

## 3. SVG 슬라이드를 생성하는 프롬프트

아래 프롬프트는 문서나 데이터를 AI에게 첨부했을 때, 슬라이드 1장짜리 SVG 파일과 React 컴포넌트를 함께 출력하도록 설계되어 있다.

```
당신은 매우 창의적인 PPT 디자이너입니다. 다음 단계를 따라 주세요:

1. 문서 분석
첨부된 문서를 주의 깊게 읽고, 시각화에 필요한 가장 중요한 핵심 사실, 수치, 인사이트를 추출하세요.

2. 슬라이드 제작
- 슬라이드는 1장만 제작합니다.
- 화면 비율: 16:9
- 테마 색상: 다크 네이비(#0D1B2A), 골드(#F4A623), 흰색(#FFFFFF), 연한 슬레이트(#E8EDF2)
- 폰트: Pretendard 사용
- 레이아웃 구조: 카드형 그리드(2×2 또는 3열) 또는 타임라인 중 데이터 성격에 맞는 구조를 선택하고, 선택 이유를 한 줄로 명시하세요.
- 시각화 스타일: 플랫 디자인 기본. 강조 수치에 한해 단색 그라데이션 제한 적용.

3. 데이터 시각화
각 데이터셋에 가장 적합한 차트 유형(선형, 막대, 원형 등)을 추천하고 생성하세요.
차트 선택 시 아래 기준을 적용하세요:
- 시계열 데이터 → 선형 차트
- 비교 데이터 → 가로 막대 차트
- 비율 데이터 → 도넛 차트(원형 차트 대신)

4. 결과물 형식
- 초기 초안용 React 컴포넌트 파일
- PowerPoint에서 추후 편집할 수 있도록 SVG 형식의 파일

5. 전반적인 디자인 가이드라인
- 텍스트와 시각 요소 사이에 충분한 여백을 두어 균형을 맞추세요.
- 제목 → 부제목 → 데이터 순으로 명확한 정보 계층 구조를 설정하세요.
- 필수 콘텐츠만 포함하고, 불필요한 텍스트는 제거하세요.
- 통계 수치와 핵심 숫자는 골드(#F4A623) 컬러로 강조하세요.
- 슬라이드 하단에 데이터 출처(Source)를 8pt 이하 소자로 표기하세요.
```

## 4. 이 프롬프트가 잘 작동하는 이유

프롬프트가 구조화되어 있는 덕분에 AI가 임의로 결정을 내리는 영역이 줄어든다. 각 항목이 하는 역할을 살펴보면 이렇다.

**색상 코드를 명시했다**
"예쁘게 만들어줘"가 아니라 `#0D1B2A`, `#F4A623`처럼 값을 직접 지정했다. AI가 색상을 추측할 필요가 없기 때문에 결과물의 예측 가능성이 높아진다.

**차트 선택 기준을 포함했다**
시계열이면 선형, 비교면 막대, 비율이면 도넛이라는 규칙을 AI에게 알려줬다. AI가 데이터 성격을 파악해 적합한 차트를 고를 때 기준이 생기므로, 엉뚱한 차트가 나오는 상황을 줄인다.

**레이아웃 선택 이유를 요청했다**
"선택 이유를 한 줄로 명시하세요"라는 조항 덕분에 AI가 선택한 레이아웃이 왜 그 레이아웃인지 확인할 수 있다. 이유가 맞지 않으면 수정 요청 시 구체적으로 방향을 잡을 수 있다.

**SVG와 React 두 가지를 요청했다**
React 컴포넌트는 브라우저에서 바로 확인할 때 유용하고, SVG는 로컬 편집이나 PowerPoint 삽입에 쓴다. 용도에 따라 선택해서 사용할 수 있다.

---

## 5. 이 프롬프트의 한계

잘 작동하는 경우가 있으면 그렇지 않은 경우도 있다.

**폰트 의존성 문제**
Pretendard 폰트는 로컬에 설치되어 있거나 SVG 내에 웹폰트로 포함되어야 한다. 설치되어 있지 않은 환경에서 SVG를 열면 폰트가 시스템 기본값으로 대체되어 디자인이 달라 보일 수 있다.

**슬라이드 1장 제한**
보고서가 여러 슬라이드로 구성되어야 한다면 이 프롬프트를 반복 실행해야 한다. 각 슬라이드마다 별도로 요청하고 결과물을 모으는 과정이 필요하다.

**다크 테마가 맞지 않는 상황**
다크 네이비 배경은 특정 기업 문화나 공식 보고서 형식에 맞지 않을 수 있다. 색상 코드를 수정해서 사용하면 해결되지만, 프롬프트를 그대로 쓰는 경우 이 점을 인식하고 있어야 한다.

**복잡한 차트의 SVG 정확도**
AI가 생성하는 SVG 차트는 간단한 구조에서는 잘 작동하지만, 복잡한 데이터셋이나 정밀한 수치 표현이 필요한 경우 오차가 생길 수 있다. 결과물을 꼭 데이터와 대조해서 검증해야 한다.

## 6. 두 방식 비교

| 항목 | AI 직접 생성 | AI → SVG → 수동 편집 |
|---|---|---|
| 초안 속도 | 빠름 | 보통 |
| 수정 용이성 | 낮음 (토큰 소모) | 높음 (로컬 편집) |
| 디자인 통제권 | 낮음 | 높음 |
| 재사용성 | 낮음 | 높음 (템플릿화 가능) |
| 도구 요구사항 | 없음 | SVG 편집 도구 필요 |
| 브랜드 일치도 | 불안정 | 안정적 (직접 조정) |
| 토큰 사용량 | 높음 (수정마다) | 낮음 (초안만 사용) |

---

## 7. 실전에서 이렇게 쓴다

**1단계**: 정리된 문서나 데이터를 AI에게 첨부하고 위 프롬프트를 붙여서 실행한다.

**2단계**: AI가 SVG 코드를 출력하면, 그 내용을 `.svg` 확장자로 저장한다.

**3단계**: Inkscape(무료), Adobe Illustrator, 또는 Figma에서 파일을 열어 필요한 부분을 직접 수정한다. 텍스트, 색상, 크기 조정 수준이라면 SVG에 익숙하지 않아도 충분히 가능하다.

**4단계**: 완성된 SVG를 PowerPoint에 그림으로 삽입하거나, 발표 시 그대로 화면에 띄운다.

---

AI가 처음부터 끝까지 만들어주는 방식이 편리해 보이는 건 사실이다. 하지만 실무에서 보고서는 거의 항상 수정된다. AI를 계속 불러서 수정 요청을 반복하는 대신, 초안 하나를 잘 뽑아두고 나머지는 직접 고치는 방식이 결과적으로 더 빠르고 통제 가능하다.

SVG라는 중간 단계를 하나 더 두는 것이 번거로워 보일 수 있지만, 한 번 익숙해지면 디자인 수정에서 AI에게 의존하는 시간이 크게 줄어든다.
