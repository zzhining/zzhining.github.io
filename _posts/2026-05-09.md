Claude Code를 처음 쓰는 사람이 가장 많이 당황하는 순간이 있다. 오후 2시에 갑자기 "사용량 한도에 도달했습니다. 7시까지 기다리거나 추가 요금을 내면 계속 사용할 수 있습니다"라는 메시지가 뜨는 것이다. "분명 $20짜리 Pro를 샀는데 왜 안 되지?" 하는 상황이다.

Claude Code의 비용 구조는 일반 SaaS 구독과 다르다. 월 고정 요금을 내더라도 "5시간 롤링 윈도우"라는 단위로 사용량이 관리된다. 이것을 모르면 예산 계획도, 작업 계획도 세울 수 없다.

이 글에서는 플랜별 요금 구조, 비용을 높이는 주요 원인, 실시간 모니터링 방법, 그리고 같은 작업을 더 적은 토큰으로 처리하는 방법을 정리한다.

## 1. 플랜 구조 한눈에 보기 — 2026년 5월 기준

**개인 사용자 플랜**

| 플랜 | 월 요금 | 연간 요금 | Claude Code 포함 | 사용량 |
|---|---|---|---|---|
| Pro | $20 | $17/월 ($204/년) | ✓ | 기준치 (1x) |
| Max 5x | $100 | 동일 | ✓ | Pro의 5배 |
| Max 20x | $200 | 동일 | ✓ | Pro의 20배 |

**팀·조직 플랜**

| 플랜 | 월 요금/인 | Claude Code 포함 | 최소 인원 |
|---|---|---|---|
| Team Standard | $20 | ✗ | 5명 |
| Team Premium | $100 | ✓ | 5명 |
| Enterprise | 별도 문의 | ✓ | 제한 없음 |

> ⚠️ **Team Standard에는 Claude Code가 없다**  
> 팀 플랜을 구매할 때 가장 많이 하는 실수가 이것이다. Team Standard는 Claude Code를 포함하지 않는다. Claude Code는 Team Premium($100/인) 이상에서만 사용할 수 있다.

## 2. 핵심 개념 — 5시간 롤링 윈도우

Claude Code의 사용량은 월 단위가 아니라 **5시간 단위**로 관리된다. 이것이 가장 중요한 개념이다.

**작동 방식**

첫 번째 프롬프트를 입력하는 순간 5시간 타이머가 시작된다. 이 5시간 안에 쓸 수 있는 토큰 양이 플랜마다 정해져 있다. 한도를 다 쓰면 타이머가 리셋될 때까지 기다리거나 추가 요금을 내야 한다.

```
예시:
오후 2:00 첫 프롬프트 입력 → 5시간 타이머 시작
오후 4:30 한도 소진
→ 오후 7:00까지 기다려야 다음 창 시작
```

**플랜별 5시간 윈도우 용량**

2026년 5월 기준 Pro 사용자는 창당 약 44,000 토큰, Max 5x는 약 88,000 토큰, Max 20x는 약 220,000 토큰을 사용할 수 있다. 단, Anthropic은 정확한 수치보다 상대적인 표현으로 한도를 설명하는 방향으로 변경했으며 모델 선택, 대화 길이, 첨부 파일, 현재 트래픽에 따라 실제 여유량이 달라진다.

**주간 한도도 별도로 있다**

2025년 8월부터 5시간 윈도우 위에 주간 한도가 추가됐다. 전체 모델에 적용되는 주간 한도와 Sonnet 모델에만 적용되는 별도 주간 한도가 함께 적용된다. 대부분의 일반 사용자는 이 주간 한도를 의식할 일이 없지만, 자동화 작업을 많이 돌리거나 하루 종일 Claude Code를 쓴다면 주간 한도에 먼저 걸릴 수 있다.

## 3. 비용을 높이는 주요 원인 5가지

같은 작업을 해도 어떻게 하느냐에 따라 토큰 소모량이 크게 달라진다.

**원인 1 — 모델 선택**

Opus 4.7은 Sonnet 4.6보다 약 1.7배 비싸다. 게다가 2026년에 새 토크나이저를 적용하면서 같은 텍스트에 대해 최대 35% 더 많은 토큰을 생성한다. 단순한 요약이나 데이터 정제 작업을 Opus로 돌리면 Sonnet 대비 2배 이상의 토큰이 소모될 수 있다.

| 모델 | API 단가 (입력/출력, MTok당) | 적합한 작업 |
|---|---|---|
| Claude Haiku | 가장 저렴 | 단순 분류, 짧은 텍스트 변환 |
| Sonnet 4.6 | $3 / $15 | 대부분의 일반 업무 |
| Opus 4.7 | $5 / $25 | 복잡한 분석, 긴 문서 이해 |

**원인 2 — 서브에이전트·에이전트 팀**

에이전트 팀은 각 팀원이 plan mode로 실행될 때 표준 세션 대비 약 7배 더 많은 토큰을 사용한다. 각 인스턴스가 독립적인 컨텍스트 창을 유지하고 별도의 Claude 인스턴스로 실행되기 때문이다. 4편에서 다룬 병렬 리서치 자동화를 자주 쓴다면 토큰 소모 속도가 크게 빨라진다.

**원인 3 — 확장 사고(Extended Thinking)**

확장 사고 토큰은 출력 토큰으로 청구되는데, 이는 입력 토큰 가격의 5배다. Opus 4.7에서는 백만 토큰당 $25이며, 기본 사고 예산이 요청당 수만 토큰에 달할 수 있다. 단순한 작업에서는 순수한 낭비다.

**원인 4 — 긴 세션의 누적 컨텍스트**

세션이 길어질수록 이전 대화 내용이 매 요청마다 다시 전송된다. 엑셀 정제 작업을 마친 뒤 같은 세션에서 완전히 다른 주제의 보고서를 작성하면, 엑셀 작업 내용이 불필요하게 보고서 작업 토큰에도 포함된다.

**원인 5 — 피크 타임**

평일 오전 5시~11시 태평양 표준시(한국 기준 오후 9시~오전 3시)에는 토큰 소모가 1.3~1.5배 빠르게 진행된다는 것이 커뮤니티에서 보고됐다. 같은 작업을 같은 플랜에서 해도 시간대에 따라 소모 속도가 달라진다.

## 4. 실시간 비용 모니터링 방법

세션 중에 현재 얼마나 썼는지 확인하는 방법이 세 가지 있다.

**`/cost` 명령어**

세션 중에 입력하면 현재 세션에서 사용한 토큰과 예상 비용을 보여준다.

```
/cost
```

```
Total cost:        $0.55
Total duration:    6m 19.7s
Tokens used:       Input 42,300 / Output 8,100
```

> 📌 **구독 플랜 사용자 주의**  
> /usage의 Session 블록에 표시되는 달러 금액은 API 사용자용이다. Pro/Max 구독자는 구독에 사용량이 포함되므로 세션 비용 수치가 실제 청구와 관련이 없다. 구독자는 같은 화면에서 플랜 사용량 바와 활동 통계를 확인한다.

**`/usage` 명령어**

현재 사용량 상세 내역을 확인한다. 5시간 윈도우에서 남은 용량과 모델별 토큰 사용 현황이 표시된다.

```
/usage
```

**`/status` 명령어**

현재 플랜, 사용 중인 모델, 세션 상태를 한눈에 확인한다.

```
/status
```

## 5. 비용을 줄이는 방법 7가지

**방법 1 — 작업 유형에 맞는 모델 선택**

모든 작업에 Opus를 쓸 필요가 없다. 단순 작업은 Sonnet으로도 충분하다.

```
/model
```

명령어로 모델을 바꿀 수 있다.

| 작업 유형 | 권장 모델 |
|---|---|
| 파일 정제, 형식 변환, 단순 요약 | Sonnet 4.6 |
| 계약서 검토, 복잡한 분석, 멀티파일 리서치 | Opus 4.7 |
| 빠른 분류, 단순 질의 | Haiku |

**방법 2 — 확장 사고 조절**

단순한 작업에서는 확장 사고를 끄거나 수준을 낮춘다.

```
/effort low      # 사고 깊이를 낮음으로 설정
/effort medium   # 기본값
/effort high     # 복잡한 문제에만 사용
```

또는 환경변수로 사고 토큰 한도를 설정한다.

```bash
MAX_THINKING_TOKENS=8000 claude
```

기본값이 수만 토큰인 것을 8,000으로 제한하면 단순 작업에서 낭비를 줄인다.

**방법 3 — 주제가 바뀌면 새 세션 시작**

한 세션에서 엑셀 정제, 경쟁사 조사, 보고서 작성을 연달아 하면 이전 작업의 맥락이 계속 누적된다. 주제가 바뀌는 시점에 `/exit`로 세션을 끝내고 새로 시작하면 컨텍스트 비대화를 막는다.

```
/exit
claude
```

**방법 4 — 서브에이전트 작업은 작게 쪼갠다**

에이전트 팀의 각 작업을 작고 독립적으로 유지해서 팀원 한 명의 토큰 사용을 제한한다. 경쟁사 10개를 한 번에 병렬 조사하는 것보다 5개씩 두 번 나눠서 처리하는 것이 컨텍스트 관리에 유리하다.

**방법 5 — 오프피크 시간대 활용**

장시간이 걸리는 자동화 작업이나 대용량 파일 처리는 저녁이나 주말에 실행하면 같은 토큰으로 더 많은 작업이 가능하다. 3편에서 다룬 Desktop 예약 작업을 활용해 금요일 저녁 10시에 실행되도록 예약해 두면 된다.

**방법 6 — CLAUDE.md로 반복 설명 제거**

매 세션마다 "한국어로 답해줘", "폴더 구조는 이렇고" 같은 설명을 반복하면 그 텍스트가 모두 입력 토큰으로 소모된다. CLAUDE.md에 한 번 설정해 두면 이후 세션에서 반복 설명이 사라진다. (CLAUDE.md 설정 방법은 [이 글](/blog/claude-md-guide)을 참고한다.)

**방법 7 — 한도 소진 직전 상황 처리**

한도 소진 메시지가 뜨기 전에 Claude Code가 경고를 보낸다. 이 경고가 뜨면 현재 작업의 중간 결과물을 먼저 저장하도록 지시한다.

```
지금 한도가 얼마 안 남은 것 같아.
지금까지 작업한 내용을 partial_result.md로 저장해줘.
다음 세션에서 이어서 작업할 수 있도록 중단 지점과 남은 작업 목록도 함께 기록해줘.
```

## 6. 내 상황에 맞는 플랜 선택 가이드

어떤 플랜이 맞는지 판단하는 가장 쉬운 방법은 한 달 사용 패턴을 파악하는 것이다.

**Pro ($20/월) 가 맞는 경우**

- 하루 1~2시간 이내로 간헐적으로 사용
- 주로 단순 파일 처리, 요약, 데이터 정제
- 아직 Claude Code를 처음 시작하는 단계
- 한 달에 한도를 다 쓰는 일이 거의 없다

대부분의 비개발자 직장인 사용자에게는 Pro로 시작하는 것을 권장한다.

**Max 5x ($100/월) 가 맞는 경우**

- Pro에서 주 2~3회 이상 한도 소진을 경험한다
- 경쟁사 조사, PDF 일괄 처리처럼 대용량 작업을 자주 한다
- 병렬 서브에이전트를 정기적으로 사용한다
- 하루 2~4시간 이상 Claude Code를 사용한다

**Max 20x ($200/월) 가 맞는 경우**

- Claude Code가 사실상 하루 종일 켜져 있다
- 자동화 루틴이 여러 개 돌아가고 있다
- Max 5x에서도 한도가 자주 찬다

**아직 어떤 플랜이 맞는지 모른다면**

Pro로 2~4주 사용해 본다. 한 달 중 한도 소진을 3회 이상 경험했다면 Max 5x로 올린다. 그래도 자주 막힌다면 Max 20x를 고려한다.

## 7. 한도 초과 시 선택지

한도가 찼을 때 Claude Code는 세 가지 옵션을 제시한다.

**옵션 1 — 기다린다**

5시간 타이머가 리셋될 때까지 기다린다. 추가 비용 없음.

**옵션 2 — Extra Usage를 활성화한다**

2026년에 Anthropic은 모든 유료 플랜에 "Extra Usage" 토글을 추가했다. 포함 한도를 다 쓴 후에도 표준 API 요금으로 계속 사용할 수 있으며, 직접 설정한 월 지출 한도 안에서만 과금된다.

Claude Code 세션 중 안내 메시지에서 "Enable extra usage"를 선택하거나, Claude Console에서 미리 활성화해 둘 수 있다. 월 한도를 설정해 두면 예상치 못한 과금을 막을 수 있다.

**옵션 3 — 플랜을 업그레이드한다**

자주 막힌다면 이 시점에서 플랜 업그레이드를 검토한다.

## 8. 주의사항 — 예상치 못한 비용이 발생하는 상황

**v2.1.100 이후 버전 토큰 인플레이션 버그**

2026년 5월 기준, Claude Code v2.1.100 이후 버전에서 토큰 소모가 약 40% 증가하는 버그가 보고됐다. 원인은 프롬프트 캐싱 오류로 인해 대화 기록이 매 요청마다 전체 재처리되는 것으로 추정된다. 평소보다 한도가 유난히 빨리 차는 느낌이 든다면 현재 버전을 확인한다.

```bash
claude --version
```

버전이 v2.1.100 이상이라면 공식 패치가 나올 때까지 주의가 필요하다.

**Claude Code와 Claude 채팅은 같은 한도를 공유한다**

Pro와 Max 플랜은 Claude Code와 Claude 채팅 간의 사용량이 공유된다. 두 도구의 모든 활동이 동일한 사용량 한도에 적용된다. Claude Code 세션을 돌리면서 동시에 claude.ai에서 채팅을 많이 하면 한도가 더 빨리 차는 것이 이 때문이다.

**API 키와 구독 플랜 혼용 주의**

API 키로 Claude Code를 인증하면 구독 플랜과 별개로 토큰당 과금이 발생한다. 구독 플랜을 쓰고 있다면 API 키 인증이 아닌 Claude 계정 로그인 방식으로 사용해야 한도 내에서만 비용이 발생한다.

## 9. 비용 효율 비교 — 실사용자 케이스

실제 사용 사례를 기반으로 플랜별 비용 효율을 정리한다.

**케이스 A: 주 3회 이내 간헐적 사용 (마케터, HR 담당자)**

하루 1~2시간, 주 2~3일 파일 처리와 보고서 작성 위주  
→ Pro($20) 권장. 월 한도 소진 가능성 낮음

**케이스 B: 매일 사용, 중간 강도 (기획자, 팀장)**
