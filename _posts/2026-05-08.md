Claude Code를 쓰다 보면 반드시 이 상황을 마주하게 된다. 어제 완료한 작업을 오늘 이어서 하려고 터미널을 열었더니, Claude Code는 어제 일을 아무것도 모른다. "우리 폴더 구조는 이렇고, 결과물은 여기 저장하고, 한국어로 써줘"를 처음부터 다시 설명해야 한다.

Claude Code는 세션이 끝나면 기억을 초기화한다. 이것은 버그가 아니라 설계다. 그리고 이 문제를 해결하기 위해 공식적으로 제공하는 도구가 **CLAUDE.md**다.

CLAUDE.md 파일을 한 번 만들어 두면, 이후 모든 세션에서 Claude Code가 자동으로 읽는다. "한국어로 답해줘"도, "결과 파일은 outputs 폴더에 저장해줘"도, "원본 파일은 절대 덮어쓰지 말아줘"도 다시 말하지 않아도 된다.

---

## 1. CLAUDE.md가 무엇인가

CLAUDE.md는 Claude Code가 시작 시 자동으로 로드하는 지침 및 컨텍스트 파일이다. 프로젝트 폴더에 이 파일이 있으면 Claude Code가 세션을 시작할 때 자동으로 읽고 그 내용을 기억한 채로 작업을 시작한다.

쉽게 말하면 **새로 합류한 동료에게 미리 전달하는 온보딩 문서**다. "우리 팀 규칙은 이렇고, 폴더 구조는 이렇고, 이것만큼은 하지 말아줘"를 담아두는 것이다.

**설정하지 않으면 어떻게 되는가**

CLAUDE.md가 없으면 Claude Code는 매 세션을 백지 상태로 시작한다. 좋은 CLAUDE.md는 반복적인 수정을 없애고 Claude가 일관되게 작동하도록 한다. 반대로 없으면 같은 설명을 반복하거나, 중요한 내용을 빠뜨려서 기대와 다른 결과물이 나온다.

---

## 2. 파일 종류와 위치 — 어디에 두느냐에 따라 적용 범위가 다르다

CLAUDE.md는 저장 위치에 따라 두 가지로 나뉜다.

| 종류 | 저장 위치 | 적용 범위 |
|---|---|---|
| **글로벌 설정** | `~/.claude/CLAUDE.md` | 모든 프로젝트에 공통 적용 |
| **프로젝트 설정** | 작업 폴더 안의 `CLAUDE.md` | 해당 폴더에서만 적용 |

**글로벌 설정**은 내 개인 기본값이다. "항상 한국어로 답해줘", "내 이름은 홍길동이고 마케팅 팀 소속이야" 같은 공통 정보를 여기에 넣는다.

**프로젝트 설정**은 특정 작업 폴더에만 해당하는 규칙이다. "이 폴더는 고객사 A 프로젝트야, 결과물은 반드시 outputs_A 폴더에 저장해줘"처럼 프로젝트마다 다른 내용을 담는다.

두 파일이 모두 있으면 둘 다 읽는다. 같은 항목이 충돌할 경우 프로젝트 설정이 우선한다.

> ⚠️ **파일 이름 대소문자 주의**  
> 반드시 `CLAUDE.md`로 저장한다. `claude.md`나 `Claude.md`는 인식하지 못한다. 대문자 CLAUDE, 소문자 .md가 정확한 형식이다.

## 3. 파일 만드는 방법

**방법 1 — `/init` 명령어로 자동 생성 (권장)**

Claude Code를 실행한 뒤 다음을 입력한다.

```bash
claude
/init
```

Claude Code가 현재 폴더를 스캔하고 기본 CLAUDE.md 초안을 자동으로 만들어준다. 이후 내용을 직접 수정해서 사용한다.

**방법 2 — 직접 만들기**

메모장(윈도우) 또는 텍스트 편집기(맥)를 열고 내용을 입력한 뒤 `CLAUDE.md`로 저장한다.

저장 위치:
- 글로벌: 윈도우 `C:\Users\홍길동\.claude\CLAUDE.md` / 맥 `~/.claude/CLAUDE.md`
- 프로젝트: 작업 폴더 안 (예: `C:\Users\홍길동\Documents\my_project\CLAUDE.md`)

> 💡 **`.claude` 폴더가 없다면**  
> 윈도우: 탐색기에서 `C:\Users\홍길동\` 이동 → 새 폴더 → `.claude`로 생성  
> 맥: 터미널에서 `mkdir -p ~/.claude` 입력

## 4. 기본 구조 — 무엇을 담으면 되는가

CLAUDE.md에는 형식이 정해져 있지 않다. 자연어로 써도 되고, 마크다운 구조로 정리해도 된다. Claude Code가 알아서 읽고 이해한다.

**핵심 항목 5가지**

```markdown
# 기본 응답 설정
- 항상 한국어로 답해줘
- 답변은 간결하게, 불필요한 서론 없이 바로 본론부터 시작해줘

# 나에 대한 정보
- 이름: 홍길동
- 소속: ABC회사 마케팅팀
- 주요 업무: 경쟁사 분석, 고객 데이터 정제, 주간 보고서 작성

# 폴더 구조
- 작업 파일: /Documents/work/
- 결과물 저장: /Documents/work/outputs/
- 원본 파일: /Documents/work/originals/ (절대 수정 금지)

# 파일 처리 규칙
- 원본 파일을 직접 수정하지 말고 항상 새 파일로 저장해줘
- 저장 파일명에는 오늘 날짜를 포함해줘 (형식: YYYY-MM-DD)
- 작업 완료 후 생성된 파일 목록을 마지막에 알려줘

# 출력 형식
- 데이터 정리 결과는 표 형식으로 정리해줘
- 긴 문서 요약 시 먼저 3줄 핵심 요약을 보여주고 상세 내용을 이어서 써줘
```

## 6. 자주 쓰는 고급 설정 항목

기본 템플릿에 상황에 따라 추가할 수 있는 항목들이다.

**반복 작업 단축**

```markdown
# 자주 하는 작업 패턴
- "주간 보고서 만들어줘"라고 하면:
  weekly_logs 폴더의 이번 주 파일을 읽고
  완료/진행중/이슈 항목을 분류해서
  weekly_report_YYYY-MM-DD.md로 저장해줘

- "경쟁사 조사해줘"라고 하면:
  competitors.txt에 있는 목록을 읽고
  병렬 서브에이전트로 각 사이트를 탐색해서
  competitor_analysis_YYYY-MM-DD.md로 저장해줘
```

**보안 규칙**

```markdown
# 절대 하지 말아야 할 것
- originals/ 폴더의 파일 수정 금지
- 파일 삭제 금지 (이동은 허용)
- 개인정보(이름, 연락처, 주민번호)가 포함된 데이터를 외부 URL로 전송 금지
- 작업 전 반드시 수행할 작업 목록을 먼저 알려줘
```

**다른 파일 참조하기**

프로젝트에 자주 참고하는 문서가 있다면 CLAUDE.md에서 직접 연결할 수 있다.

```markdown
# 참고 문서
- 회사 브랜드 가이드라인: @docs/brand_guidelines.md
- 보고서 작성 템플릿: @templates/report_template.md
- 데이터 처리 규칙: @rules/data_handling.md
```

`@` 뒤에 파일 경로를 적으면 Claude Code가 세션 시작 시 해당 파일도 함께 읽는다.

## 7. 설정 적용 확인 방법

CLAUDE.md를 작성한 뒤 제대로 읽히는지 확인하려면 새 세션을 시작하고 다음을 입력한다.

```
지금 로드된 CLAUDE.md 내용을 요약해서 알려줘.
어떤 규칙과 설정이 적용되어 있어?
```

Claude Code가 CLAUDE.md의 내용을 읽어서 현재 적용 중인 설정을 확인해준다. 원하는 내용이 빠져있거나 잘못 인식됐다면 파일을 수정한 뒤 세션을 재시작한다.

## 8. CLAUDE.md 수정하는 방법

**방법 1 — 직접 파일 수정**

메모장이나 텍스트 편집기로 파일을 열어서 내용을 수정하고 저장한다.

**방법 2 — 대화 중 요청**

세션 중에 Claude Code에게 바로 수정을 요청할 수 있다.

```
지금 CLAUDE.md에 다음 규칙을 추가해줘.
"모든 파일 저장 시 백업본을 _backup 폴더에 함께 저장해줘"
```

Claude Code가 파일을 직접 열어서 내용을 추가한다.

**방법 3 — `/memory` 명령어**

세션 중에 학습한 내용을 기억에 추가할 수 있다.

```
/memory
```

현재 메모리 파일 목록과 내용을 확인하고, 추가 또는 삭제할 수 있다.

## 9. 자주 하는 실수와 해결법

**설정한 내용이 적용되지 않는다**

가장 흔한 원인은 파일 이름 오류다. `claude.md`, `Claude.md`, `CLAUDE.MD`는 모두 인식되지 않는다. 정확히 `CLAUDE.md`인지 확인한다.

두 번째 원인은 위치 오류다. Claude Code를 실행한 폴더에 CLAUDE.md가 있어야 한다. 다른 폴더에서 실행하면 해당 폴더의 CLAUDE.md를 읽는다. 현재 위치를 `pwd`(맥) 또는 `cd`(윈도우)로 확인한다.

**글로벌 설정과 프로젝트 설정이 충돌한다**

같은 항목이 두 파일에 다르게 설정돼 있으면 프로젝트 설정이 우선한다. 의도적이라면 그대로 두고, 의도하지 않은 것이라면 한쪽을 삭제한다.

**파일이 너무 길어져서 느려진다**

CLAUDE.md 파일이 지나치게 길면 매 세션마다 토큰을 많이 소모한다. 실제로 자주 쓰는 내용만 남기고, 특정 작업에만 필요한 상세 규칙은 별도 파일(`@rules/detail.md`)로 분리해서 필요할 때만 참조하도록 한다.

**이전에 설정한 내용을 모두 초기화하고 싶다**

파일 내용을 전부 지우거나 파일 자체를 삭제하면 된다. 글로벌 설정만 지우고 프로젝트 설정을 유지하거나, 반대로 할 수도 있다.
