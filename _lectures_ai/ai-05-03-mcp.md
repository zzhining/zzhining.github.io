오늘은 **MCP(Model Context Protocol)와 AI 통합의 새로운 표준**을 이야기합니다.

---

1. **지금 AI 통합 시장에 표준 전쟁이 끝났습니다.** 2024년 말 Anthropic이 MCP(Model Context Protocol)를 오픈소스로 공개했고, 2025년부터 OpenAI·Google·Microsoft가 차례로 지원을 선언했습니다. 표준이 하나로 수렴하는 중입니다. 기획자가 지금 이걸 모르면 AI 도입 비용 계산을 잘못하게 됩니다.

2. **MCP 이전에는 AI를 시스템에 연결하는 방식이 제각각이었습니다.** Slack에 AI를 붙이는 코드, Google Drive에 AI를 붙이는 코드, 사내 데이터베이스에 AI를 붙이는 코드가 전부 따로 놀았습니다. 새로운 AI 모델로 갈아타면 그 작업을 처음부터 다시 해야 했습니다. 매번 커스텀 개발이었습니다.

3. **MCP는 USB 같은 개념입니다.** USB가 등장하기 전에는 프린터·키보드·마우스마다 다른 포트가 필요했습니다. USB가 표준이 되자 어떤 기기든 꽂으면 됐습니다. MCP는 AI와 외부 시스템 사이의 USB입니다. 한 번 MCP 서버를 만들면 어떤 AI든 연결할 수 있습니다.

4. **MCP의 구조는 세 가지로 이루어집니다.** MCP 호스트(AI 애플리케이션), MCP 클라이언트(연결을 관리하는 부분), MCP 서버(외부 시스템에 붙어 기능을 제공하는 부분)입니다. 기획자가 관심을 가져야 할 것은 MCP 서버입니다. 우리 회사 시스템에 MCP 서버를 만들면 AI가 그 시스템을 쓸 수 있게 됩니다.

5. **MCP 서버가 하나 생기면 모든 AI에서 씁니다.** 구글 드라이브 MCP 서버를 만들어두면 Claude도, GPT도, Gemini도 그 서버를 통해 구글 드라이브에 접근합니다. AI를 바꿔도 연결 코드를 다시 짤 필요가 없습니다. 이것이 기획자 입장에서 MCP가 중요한 핵심 이유입니다.

6. **이미 수천 개의 MCP 서버가 공개되어 있습니다.** Slack, Notion, GitHub, Google Drive, Jira, Salesforce, PostgreSQL, Figma 등 주요 서비스들의 MCP 서버가 이미 오픈소스로 공개되어 있습니다. 2026년 현재 직접 만들지 않아도 가져다 쓸 수 있는 MCP 서버가 대부분입니다.

7. **기업이 MCP를 도입하면 AI 도입 비용 구조가 바뀝니다.** 과거에는 "AI와 CRM 연동"에 수천만 원짜리 커스텀 개발이 필요했습니다. MCP 서버가 있으면 기존 개발 비용의 10분의 1로 줄어드는 경우가 나오고 있습니다. 비용 계산을 다시 해야 합니다.

8. **MCP가 없는 AI 통합은 기술 부채를 쌓는 것**입니다. 지금 당장 급하다고 커스텀 방식으로 연결하면, 나중에 AI 모델을 바꾸거나 시스템을 업그레이드할 때 다 뜯어고쳐야 합니다. 새 프로젝트라면 처음부터 MCP 기반으로 설계하는 것이 장기적으로 훨씬 유리합니다.

9. **MCP는 보안 설계도 함께 제공합니다.** MCP 서버는 어떤 도구를 어떤 권한으로 노출할지를 명시적으로 정의합니다. AI가 할 수 있는 것과 없는 것의 경계선이 서버 설계 단계에서 결정됩니다. 보안을 나중에 덧붙이는 것이 아니라 구조에 내장하는 방식입니다.

10. **사내 시스템에 MCP 서버를 붙이는 것은 개발자 혼자 결정할 수 없습니다.** 어떤 데이터를 AI에게 노출할 것인지, 어떤 작업을 AI가 실행할 수 있게 할 것인지는 비즈니스 판단입니다. 기획자가 "우리 CRM의 어떤 기능을 AI가 써야 하는가"를 먼저 정의해야 개발자가 MCP 서버를 만들 수 있습니다.

11. **MCP Remote는 클라우드 AI 서비스의 게임 체인저**입니다. 초기 MCP는 로컬 환경에서만 작동했지만, MCP Remote가 등장하면서 원격 서버에서도 MCP를 쓸 수 있게 됐습니다. 사내 시스템을 외부 AI 서비스와 안전하게 연결하는 것이 이제 현실적입니다.

12. **AI 에이전트 플랫폼 선택 기준에 MCP 지원이 들어가야 합니다.** 벤더사에 AI 솔루션을 도입할 때 "이 제품이 MCP를 지원합니까"를 반드시 물어봐야 합니다. MCP를 지원하지 않는 솔루션은 나중에 다른 시스템과 연동할 때 비용이 추가로 발생합니다.

13. **MCP는 AI 에이전트의 '플러그인 생태계'를 만들고 있습니다.** 스마트폰에 앱스토어가 생기면서 기능이 폭발적으로 늘어난 것처럼, MCP 생태계가 커지면서 AI가 할 수 있는 일이 매달 늘어납니다. 기획자는 "새로운 MCP 서버가 뭐가 생겼나"를 주기적으로 확인하는 습관이 필요합니다.

14. **MCP를 모르면 AI 도입 RFP를 잘못 씁니다.** AI 통합 프로젝트의 제안요청서에 "커스텀 API 개발"을 명시하면 벤더사는 그걸로 견적을 냅니다. MCP 서버 기반으로 다시 쓰면 제안 방식이 달라지고 비용도 달라집니다. 발주자가 알아야 제대로 된 RFP가 나옵니다.

15. **MCP는 AI 시대의 기획자 언어**입니다. 과거 기획자가 REST API가 무엇인지 알아야 개발자와 소통할 수 있었던 것처럼, 지금은 MCP를 알아야 AI 통합 프로젝트에서 제대로 된 의사결정을 할 수 있습니다. 모르면 개발자가 결정합니다. 그 결정이 나중에 비즈니스 문제가 됩니다.

---

**마무리**

1. MCP는 기술 표준이지만 그 영향은 비즈니스 전략에 닿습니다. AI 도입 비용 계산, 벤더 선택 기준, 사내 시스템 연동 우선순위가 MCP를 아느냐 모르느냐에 따라 달라집니다. 이건 개발팀에게만 맡겨둘 수 없는 문제입니다.

2. 지금 당장 우리 회사 핵심 시스템 목록을 꺼내보세요. CRM, ERP, 사내 메신저, 데이터베이스. 이 중에 MCP 서버가 이미 있는 것이 얼마나 됩니까. 있다면 AI 도입 비용이 예상보다 훨씬 낮아질 수 있습니다.

3. 표준을 먼저 아는 사람이 설계권을 가집니다. MCP 기반으로 AI 통합 로드맵을 먼저 그리는 기획자가 이후 3년간 사내 AI 프로젝트의 방향을 결정하게 됩니다.
